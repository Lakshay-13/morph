# Registering formats and engines

Morph's format graph is in `Sources/MorphCore/EngineRegistry.swift`; models and engine metadata are in `Models.swift`; adapters are registered by `ConversionService.defaultEngines(for:)` in `ConversionService.swift`.

## Add a format

1. Add a `MorphFormat` entry to `ConversionCatalog.formats` with its extension, display label and `FormatCategory`.
2. Add the extension mapping to the relevant capability probe. Do not add a route for a format that the adapter cannot read or write.
3. Add input/output route creation in `ConversionCatalog.buildRoutes` with the category check and required engine capability.
4. Add the extension to the adapter's format mapping and implement any required codec parameters.
5. Extend `OutputValidator` so generated outputs of a structured or container format receive a format-specific validity check where practical.
6. Add actual fixture-based conversions and verify output properties and the input checksum in `Tests/MorphChecks/main.swift`.
7. Update `docs/TEST_REPORT.md`, the README format table and known limitations only after the conversion is executed.

Multi-part extensions such as `.tar.gz` are recognized by `URL.morphExtension(knownExtensions:)`, which tries longer registered suffixes first.

FFmpeg demuxer aliases must be mapped to file extensions, not just to output extensions. Keep the mapping synchronized with `FFmpegInputFormat` and `FFmpegEngine`; every muxer output exposed by the probe must have a corresponding implemented encoder case. Conversion and FFprobe validation pass a format whitelist derived from the file extension, preventing playlist demuxers from being auto-selected for ordinary media files. M4A and AAC capability probes use the `m4a` and `aac` aliases; their input whitelist maps to MOV/MP4 and AAC/ADTS demuxers. WMA is carried by the ASF demuxer and muxer. GIF is an image/video format without an audio stream, so it must not receive audio-extraction routes.

ImageMagick's format table can overstate usable output support. Morph's raster policy denies SVG and delegate coders, so SVG is not an advertised ImageMagick input or output. Run the discovered image-route sweep in `Scripts/run-checks.sh` after changing capability filters so advertised image targets have an executable conversion path on the current machine.

PDF page-image export is presented as **PNG images** in Finder. A one-page PDF writes one `.png` directly; multipage PDFs render numbered PNGs and group them into a `.zip`. PDF operations accept regular files up to 512 MB and 1,000 pages. Rendering caps each raster page at 16 million pixels, the operation at 256 million total rendered pixels and generated page images at 1 GB; cancellation is checked between pages. The Finder label omits the container extension because the requested conversion is to page images.

Structured-data routes are implemented by `StructuredDataEngine`. JSON/YAML/TOML objects can convert between those formats; CSV and TSV require arrays of string-keyed records, and TOML represents a top-level record array under `records`. XML bridges JSON, YAML and TOML. Keep parsing limits and generated-output validation in place when adding structured formats. YAML node graphs are checked against depth, node-count and scalar-expansion budgets before Foundation values are constructed; bounded aliases are accepted, while oversized expansions and non-scalar mapping keys are rejected. Preserve those checks when updating Yams. Parser package versions and licenses are recorded in `Package.swift`, `Package.resolved` and `docs/THIRD_PARTY.md`.

LibreOffice routes are constrained to text-document, presentation or spreadsheet families, with PDF export from each family. Do not generate a Cartesian product across all office extensions: a file extension alone does not make cross-family conversions meaningful or supported.

## Add an engine

1. Add an `EngineID` case, display name, Homebrew package name and kind (formula or cask), executable candidates and plain-language summary in `Models.swift`.
2. Add an explicit executable-approval candidate list, including directly invoked helper tools such as FFprobe. Do not run an unreviewed candidate to obtain its version or capabilities.
3. Add a capability probe in `EngineRegistry.probeCapabilities`. Probe actual runtime support; do not infer codecs from container names alone.
4. Add a `ConversionEngine` adapter in `ConversionService.swift`. It receives a `ConversionContext` and must write only to `temporaryOutputURL`.
5. Register the adapter in `defaultEngines(for:)` and create routes only when its engine is approved, passes its version floor, and exposes the required input/output capabilities.
6. Use `ProcessRunner` with a canonical executable URL from Morph's fixed search locations and individual arguments. Do not trust inherited `PATH` or saved executable URLs, use `/bin/sh`, interpolate untrusted input into a command string, or run commands embedded in files.
7. Ensure cancellation reaches child processes, outputs are validated, and failure removes staged files. Use temporary working directories for tools that write to their input basename.
8. Add consent-aware install/update/uninstall UI only if Morph has a safe package path and the engine's license is documented in `docs/THIRD_PARTY.md`.
9. Add positive, failure, malformed-input and source-preservation checks.

PDF compression is an operation adapter rather than a PDF → PDF conversion route. The Ghostscript executable remains external; invocation uses `-dSAFER`, fixed quality presets, an isolated staged output and PDFKit page-count validation. When Ghostscript is absent, the app asks for explicit approval before installing its Homebrew formula and retries the requested compression only after rediscovery succeeds.

Video compression is also an operation adapter rather than a format edge. It requires a detected FFmpeg route from each selected input to MP4, uses fixed H.264/AAC arguments, supports batch inputs and user-selected quality/resolution limits, and validates output media duration and dimensions before publishing collision-safe copies. If FFmpeg is missing, Morph requests explicit install consent and resumes the selected operation only after rediscovery succeeds.

## Engine contract

`ConversionEngine.convert(context:)` is synchronous and runs on a background task. It should throw `MorphError` with a useful message, honor `context.cancellation`, never replace the original, and never publish a partial destination. When more than one route exists, the service tries them in deterministic priority order and falls back after an adapter failure. New adapters may be supplied to `ConversionService` for tests; they augment the default adapters and can replace one by engine ID.

## Engine security floors

`EngineExecutableTrust` stores explicit SHA-256 approvals in the Data Protection Keychain under a team-prefixed access group shared by the signed app and Finder helper. An approval is scoped to the engine role and canonical executable path, and remains until revoked or the executable digest changes; it is not tied to the Morph build version. Ad-hoc builds cannot persist the protected approval, so external engines, Homebrew actions and custom output folders fail closed. The Engines view presents exact paths and digests before approval and offers revocation. Morph verifies the digest before probing and again before execution; an unapproved or changed file fails closed. Homebrew has a separate executable approval in addition to the package-action confirmation. A custom output folder is pinned by path and device/inode in the protected record; stale UserDefaults values do not redirect output. Digest approval does not pin dynamically loaded libraries, data files or other dependencies within the engine installation and cannot remove all check/use races.

`EngineSecurityPolicy` checks approved external tools before capability probing and rechecks the exact executable immediately before FFmpeg, ImageMagick, LibreOffice and Pandoc conversions. LibreOffice's Homebrew launcher must be the exact two-line form Morph recognizes, and its literal target must resolve to the expected app/Caskroom location. Morph checks the app bundle's complete strict code signature, all nested code and resources against Developer ID Team ID `7P5S3ZLCN7` and bundle identifier `org.libreoffice.script`, then runs the native Mach-O directly, never the shell wrapper. The SHA-256 approval covers that native executable. LibreOffice is invoked through a macOS sandbox profile that denies outbound connections, inbound IP listeners, descendant executable launches, process forks, hard links, file clones, job creation, Apple Events, LaunchServices opens, signals to other processes, preference access and selected sensitive Mach service lookups. It permits default system reads and unlisted Mach services, so it is not a complete OS sandbox. Morph verifies that generated files are regular, current-user-owned and have one hard link before validation or publication. LibreOffice output is snapshotted into a second Morph-owned stage before validation or sanitization. Routes appear only after a private CSV-to-XLSX conversion probe succeeds; a failed or timed-out probe disables them. FFmpeg conversion, trim and compression use an output file-size ceiling; Morph requires FFprobe to validate generated media. Ghostscript is rechecked before PDF compression reads input, and its PDF path rejects PostScript-prefixed inputs. Video trim and compression also check both FFmpeg and FFprobe before they inspect input files. Discovery and execution share engine-specific version arguments and banner parsers; a missing or malformed engine version fails closed instead of accepting a compiler or library version from later in the output. The current minimums are FFmpeg 9.0.2, ImageMagick 7.1.2-36, Pandoc 3.14, Ghostscript 10.08.0, 7-Zip 26.06, LibreOffice 26.2.7 on the 26.2 branch, or LibreOffice 26.8.2 on the 26.8 branch. `Scripts/install-ci-engines.sh` refreshes Homebrew metadata, upgrades installed formulae or installs missing ones, and checks that each installed version meets Morph's security floor; it installs 7-Zip on arm64, where archive-engine checks run. Update these minimums alongside `EngineSecurityPolicy` and its regression cases. On arm64, `Scripts/install-ci-libreoffice.sh` installs the versioned CI-only Cask at 26.8.3. The CI workflow does not install Poppler because PDF text extraction uses PDFKit. Morph requires Pandoc's current upstream release because its [security policy](https://github.com/jgm/pandoc/security/policy) provides updates only for the latest release; the current release is listed in the [release history](https://pandoc.org/releases.html). Route creation requires `canConvert`; unapproved or blocked engines must not leak routes through the direct route builder. The Ghostscript floor addresses CVE-2026-39919. The Pandoc adapter omits PDF output, CSV and generic JSON AST conversion, and `--extract-media`; `--sandbox` alone is not a mitigation for GHSA-xj5q-fv23-575g. The Engines view keeps installed status visible, explains the minimum version and approval status, and offers a user-confirmed update. These are reviewed floors, not a guarantee that engines have no other vulnerabilities. PDF text extraction is provided by PDFKit, so Poppler is no longer an optional runtime engine.

ImageIO identifiers are intersected with Morph's explicit common-raster allowlist. Writable types are verified with a private 2 × 2 probe image before Morph adds them to the output set. Inputs are checked so the detected type matches the filename extension. This keeps unreviewed types such as RAW, PSD, EXR and KTX out of the in-process decoder. The capability result is cached for the process lifetime; temporary probe files are removed immediately.
