## Product architecture

1. **MorphCore Swift package:** format definitions, conversion graph, engine discovery, conversion job model, safe output naming, process runner, history/settings storage and native conversion adapters. Keep engine selection independent of UI.
2. **Native app:** SwiftUI macOS app with a navigation sidebar for Overview, Convert, History, Engines and Settings. Use standard system controls and materials, with a Liquid Glass prominent primary action on macOS 26 and a bordered native fallback on macOS 14–25. Keep content surfaces readable and let system controls adapt to accessibility settings.
3. **Finder entry point:** embed a sandboxed Finder Sync extension with a dynamic contextual submenu. It gets the current selection from Finder, intersects available routes across selected files and labels outputs with their source formats. The extension sends the selection and format to a persistent windowless helper. The helper checks that each request's Apple Event sender is the installed Finder Sync extension; on cold launch the extension starts it without request data in arguments, then retries the URL with a UUID request ID for deduplication. Conversion runs without opening the main app or a format-picker window. The submenu appears directly in Finder's contextual menu, not inside the built-in Quick Actions group. The extension monitors the user's home folder and mounted, network and shared roots. Live menu, cold-start conversion and background behavior are verified in `TEST_REPORT.md`; ad-hoc signing still blocks public release validation.
4. **Engine adapters:** native ImageIO/PDFKit for system-supported image and PDF work; fixed-argument process adapters for approved FFmpeg, ImageMagick, Pandoc and other catalogued tools. libvips is not auto-discovered because it has no adapter. Resolve executables only from fixed Homebrew, MacPorts and system locations, never through a shell or inherited `PATH`. Require a Keychain-backed SHA-256 review before an external executable is probed or run; show installed-but-unapproved engines without routes. Enforce reviewed version floors and only advertise verified capability edges. PDF text extraction uses PDFKit instead of Poppler.
5. **Dependency manager:** discovery has no download or package-manager side effects. The engine screen shows installed versions, approval status and route examples; users review executable paths/digests, approve Homebrew separately, then confirm each install/update/uninstall action. Homebrew performs package resolution only after explicit action approval; Morph currently does not estimate download size. Formula and cask actions refresh detected capabilities after success. Do not bundle engines in the first release.
6. **Safe conversion pipeline:** convert into unique private workspaces, validate output, copy it through descriptor-pinned stages, then publish to a collision-safe final name. Preserve sources, avoid overwrites, support cancellation, enforce resource budgets and clean up only Morph-owned temporary files. Custom output folders are bound to a protected Keychain path and directory identity.

## Work phases

1. **Foundation:** package manifest, app entry point, app metadata, assets, ignore rules, development scripts and this plan.
2. **Core:** format/engine registry, capability probes, safe conversion job/output pipeline, native data/image/PDF operations and external process adapters.
3. **Application:** native dashboard, file picker/drop intake, Finder Service, format choice, batch queue, progress/cancel, history, output location and engine consent flow.
4. **Operations:** image resize, image/PDF metadata inspection and metadata-edit copies for PDF/JPEG/TIFF, previewed batch rename copies, PDF merge/page-range extraction/split/compression, ZIP extraction and ZIP/TAR.GZ/7z repackaging, FFmpeg video trimming and batch compression, and JSON/YAML/TOML transformations are implemented and checked. Metadata copies support PDF title/author/subject/keywords and image IPTC title/subject/keywords. Keep the catalogue honest about unsupported font, CAD, geospatial and specialist conversions.
5. **Quality:** unit tests, fixture-based end-to-end tests, 12+ real format-pair conversions, security/failure/collision/cancellation checks, and a Finder smoke test.
6. **Documentation:** README, architecture and engine registration guide, tested capability matrix, known limitations, security/privacy notes, contribution guidance and third-party license attribution.
7. **Release:** reproducible arm64/x86_64 build where toolchain support permits, app archive/DMG, checksums, signing/notarization workflow, GitHub release and Cask audit. Do not ask users to bypass Gatekeeper.
8. **Install/distribute:** install to the current user’s Applications folder, register and verify Finder integration, exercise installed conversions, push all intended commits, and submit an upstream Cask PR only if the published artifact meets current Homebrew policy and GitHub access is available.

## Validation and release gates

- The baseline self-contained SwiftPM harness run reported **28 groups passed, 0 failed and 0 skipped**. The 2026-11-19 security-hardening run reports **35 groups passed, 0 failed and 0 skipped**. New coverage exercises bounded process output/environment/timeouts/process-group cancellation, concurrent private history writes, YAML alias-expansion and node-key limits, ZIP local/central metadata and expansion budgets, TAR listing checks, frame preservation, output cleanup, and Finder labels; it also retains the real conversion matrix across images, audio/video, documents, spreadsheets, structured data, PDF and archives. Video compression validates H.264/AAC output, size/dimensions/duration, collisions and source preservation. `sevenzip 26.06` is installed on the arm64 Mac; ZIP ↔ 7z also passed on arm64 CI. See `TEST_REPORT.md`.
- Cover mixed and batch inputs, unsupported/missing engines, failed and invalid inputs, collisions, cancellation, cleanup and large inputs where practical.
- GitHub Actions run [44225822929](https://github.com/Lakshay-13/morph/actions/runs/44225822929) on commit `2912c87` passed the real-file conversion checks on both macOS 26 arm64 and x86_64 runners. The arm64 job installed 7-Zip and exercised ZIP ↔ 7z; its universal-package job passed the Homebrew Cask audit and style checks, both architecture slices, signature and license checks, ZIP integrity and checksum verification. The packaged app has not been installed and launched on a physical Intel Mac; Cask install/uninstall are also unverified, and the CI archive remains ad-hoc signed.
- An earlier x86_64 `MorphChecks` debug harness ran under Rosetta on this Apple Silicon Mac with **27 passed, 0 failed, 0 skipped**. This is not a physical Intel Mac test. An earlier working tree was packaged as a universal ZIP in `dist/release-0.1.0-current`; the app, helper and Finder extension each contain both architecture slices, and signature, ZIP and checksum checks passed. That archive was ad-hoc signed; Gatekeeper and public distribution validation remain outstanding.
- The earlier Quick Action build displayed Morph in Finder's built-in Quick Actions list and exercised PDF compression, PNG → JPEG, WebP, page-range extraction, metadata inspection and video trimming. That integration was superseded by the current Finder Sync submenu design. The live dependency confirmation was opened and cancelled; an install was not approved or run.
- The earlier helper build was launched from Quick Action with a selected PNG; the accessory helper stayed open while its format popover was shown, and the main Morph app stayed closed. The CUA accessibility surface did not expose the popover's format rows, so the older popover flow was not fully verified. The updated Finder Sync live verification is recorded in `TEST_REPORT.md`.
- An earlier Finder Sync smoke test did not show the menu because the extension resolved its sandbox container instead of the user's real home directory. The monitored-home path and settings snapshot handoff were corrected. Current live Finder results are recorded in `TEST_REPORT.md`.
- The follow-up security review fixes process environment inheritance, Pandoc/FFmpeg resource protocols, YAML expansion and key validation, CSV CRLF/extra-column handling, pre-extraction archive path/type/size checks, cancellation and output cleanup, image-frame loss, Finder labels, history races, package-type flags, release metadata/signing flags, and installer replacement behavior. The `MorphChecks` suite passes on this Mac; the independent security-review retest is pending. Developer ID signing and notarization remain blocked by the account/identity requirements recorded in `RELEASING.md`.
- Homebrew distribution requires a stable upstream artifact, checksum, local install/uninstall checks and Gatekeeper-compliant distribution. Homebrew's current self-submission policy normally requires 90 forks, 90 watchers or 225 stars; this repository currently has no independent-interest evidence. Recently released apps may receive further consideration only with substantial, independently verifiable public interest and multiple requests. Use a project-maintained tap for the initial release, then reconsider an official `homebrew/cask` submission if the project becomes eligible. Signing/notarization is blocked until an Apple Developer Program team with Developer ID access is available and its certificate and notarytool Keychain profile are configured. The GitHub Actions Cask audit and style checks pass; the local audit remains blocked because Homebrew prefers the existing CLT SDK over the selected Xcode SDK. Download Command Line Tools for Xcode 27.0 from Apple Developer Downloads before retrying the local audit.
- No engine or system dependency may be installed by the agent without a distinct explicit user approval.
