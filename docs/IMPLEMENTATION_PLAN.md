- The development machine is an Apple Silicon Mac running macOS 26.6.2. FFmpeg, ImageMagick, libvips, Pandoc, Ghostscript, Poppler and LibreOffice executables are present. Morph 0.1.0 is installed in the current user's Applications folder with its Finder Quick Action registered.
- Xcode 27.0 is selected and its license was accepted on 2026-11-18. The Apple Account is now signed into Xcode, but only a Personal Team is available; Manage Certificates offers no enabled certificate creation option and does not offer Developer ID Application. There are zero valid signing identities and no `morph-notary` profile. Developer ID certificate creation requires an eligible team and Account Holder role; see `RELEASING.md`. Hosted CI passes the Cask audit and style checks.

## Product architecture

1. **MorphCore Swift package:** format definitions, conversion graph, engine discovery, conversion job model, safe output naming, process runner, history/settings storage and native conversion adapters. Keep engine selection independent of UI.
2. **Native app:** SwiftUI macOS app with a navigation sidebar for Overview, Convert, History, Engines and Settings. Use standard system controls and materials, with a Liquid Glass prominent primary action on macOS 26 and a bordered native fallback on macOS 14–25. Keep content surfaces readable and let system controls adapt to accessibility settings.
3. **Finder entry point:** install a native Automator Quick Action for file selections. Finder passes selected file URLs to Morph; Morph opens a focused target-format picker and runs the selected conversion. Keep originals untouched. Finder Sync is not appropriate for a general converter because Apple positions it for synchronization UI in monitored folders. The deliberate tradeoff is one Quick Actions selection followed by choosing a format in Morph, rather than injecting a custom top-level Finder submenu.
4. **Engine adapters:** native ImageIO/Quartz for system-supported image and PDF work; fixed-argument process adapters for installed FFmpeg, ImageMagick, libvips, Pandoc, Poppler and other explicitly catalogued tools. Resolve executables from known locations/PATH, never through a shell. Store exact capability edges and only show them when their engine and codecs are available.
5. **Dependency manager:** read-only discovery at launch; no downloads or updates in the background. The engine screen shows installed versions and route examples; installation estimates the selected formula bottle size when available, then requires a separate affirmative user action, runs a fixed Homebrew formula invocation, and refreshes detected capabilities after success. Do not bundle engines in the first release.
6. **Safe conversion pipeline:** stage output beside the destination in a unique temporary path, validate it, then move it to a collision-safe final name. Preserve sources, avoid overwrites, support cancellation and clean up only Morph-owned temporary files.

## Work phases

1. **Foundation:** package manifest, app entry point, app metadata, assets, ignore rules, development scripts and this plan.
2. **Core:** format/engine registry, capability probes, safe conversion job/output pipeline, native data/image/PDF operations and external process adapters.
3. **Application:** native dashboard, file picker/drop intake, Finder Service, format choice, batch queue, progress/cancel, history, output location and engine consent flow.
4. **Operations:** image resize, image/PDF metadata inspection, previewed batch rename copies, PDF merge/page-range extraction/split/compression, ZIP extraction and ZIP/TAR.GZ repackaging, FFmpeg video trimming, and JSON/YAML/TOML transformations are implemented and checked. Metadata inspection is read-only; metadata editing remains unimplemented. Keep the catalogue honest about unsupported font, CAD, geospatial and specialist conversions.
5. **Quality:** unit tests, fixture-based end-to-end tests, 12+ real format-pair conversions, security/failure/collision/cancellation checks, and a Finder smoke test.
6. **Documentation:** README, architecture and engine registration guide, tested capability matrix, known limitations, security/privacy notes, contribution guidance and third-party license attribution.
7. **Release:** reproducible arm64/x86_64 build where toolchain support permits, app archive/DMG, checksums, signing/notarization workflow, GitHub release and Cask audit. Do not ask users to bypass Gatekeeper.
8. **Install/distribute:** install to the current user’s Applications folder, register and verify Finder integration, exercise installed conversions, push all intended commits, and submit an upstream Cask PR only if the published artifact meets current Homebrew policy and GitHub access is available.

## Validation and release gates

- The self-contained SwiftPM harness currently runs 21 groups, covering 31 distinct format pairs plus PDF page-range extraction, PDF compression, video trimming and collision-safe batch rename copies, malicious ZIP path/symlink rejection, image/PDF metadata inspection, route-aware conversion presets, real engine conversions, safe outputs, source checksums, collision handling, invalid input, missing engines, fallback, cancellation, office-route family constraints and a large image. See `TEST_REPORT.md`.
- Cover mixed and batch inputs, unsupported/missing engines, failed and invalid inputs, collisions, cancellation, cleanup and large inputs where practical.
- Latest GitHub Actions run [44202178369](https://github.com/Lakshay-13/morph/actions/runs/44202178369) on commit `ce57117` passed the real-file conversion checks on both macOS 26 arm64 and x86_64 runners. Its universal-package job passed the Homebrew Cask audit and style checks, both architecture slices, signature and license checks, ZIP integrity and checksum verification. The packaged app has not been installed and launched on a physical Intel Mac; Cask install/uninstall are also unverified, and the CI archive remains ad-hoc signed.
- The Finder right-click Quick Actions submenu displays the Morph action; a selected PDF was imported and compressed end to end through the actual context menu. Finder Services and the installed Automator workflow also imported selected files; the installed app completed PNG → JPEG, WebP preset conversion, PDF compression, page-range extraction, image metadata inspection and video trimming. The live dependency confirmation was opened and cancelled; an install was not approved or run.
- Homebrew distribution requires a stable upstream artifact, checksum, local install/uninstall checks and Gatekeeper-compliant distribution. The project repository was created on 2026-11-17 and has 0 stars; Homebrew's current policy normally excludes repositories under 30 days old. Its public-interest thresholds are 30 forks, 30 watchers or 75 stars for a typical submission, and 90 forks, 90 watchers or 225 stars for an owner self-submission. Use a project-maintained tap for the initial release, then consider an official `homebrew/cask` submission if the repository becomes eligible. Signing/notarization is blocked until an eligible Apple Developer Program account is added and its Developer ID certificate and notarytool Keychain profile are configured. The GitHub Actions Cask audit and style checks pass; the local audit remains blocked because Homebrew prefers the existing CLT SDK over the selected Xcode SDK. Download Command Line Tools for Xcode 27.0 from Apple Developer Downloads before retrying the local audit.
- No engine or system dependency may be installed by the agent without a distinct explicit user approval.
