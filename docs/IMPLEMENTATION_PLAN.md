The hosted run on `f9c7b94` passed both architecture test jobs, the Cask audit/style checks and universal package verification.

## Product architecture

1. **MorphCore Swift package:** format definitions, conversion graph, engine discovery, conversion job model, safe output naming, process runner, history/settings storage and native conversion adapters. Keep engine selection independent of UI.
2. **Native app:** SwiftUI macOS app with a navigation sidebar for Overview, Convert, History, Engines and Settings. Use standard system controls and materials, with a Liquid Glass prominent primary action on macOS 26 and a bordered native fallback on macOS 14–25. Keep content surfaces readable and let system controls adapt to accessibility settings.
3. **Finder entry point:** embed a sandboxed Finder Sync extension with a dynamic contextual submenu. It gets the current selection from Finder, intersects supported native routes across selected files and labels outputs with their source formats. One Launch Services open operation sends the selection and requested format to a windowless helper; conversion runs without launching the main app or a format-picker window. The submenu appears directly in Finder's contextual menu, not inside the built-in Quick Actions group. The extension monitors the home folder and mounted/network/shared roots. The latest ad-hoc local build registers and launches the extension, but Finder does not show its menu; a valid signing identity is required to complete the live smoke test.
4. **Engine adapters:** native ImageIO/Quartz for system-supported image and PDF work; fixed-argument process adapters for installed FFmpeg, ImageMagick, libvips, Pandoc, Poppler and other explicitly catalogued tools. Resolve executables from known locations/PATH, never through a shell. Store exact capability edges and only show them when their engine and codecs are available.
5. **Dependency manager:** read-only discovery at launch; no downloads or updates in the background. The engine screen shows installed versions and route examples; installation estimates the selected formula bottle size when available, then requires a separate affirmative user action, runs a fixed Homebrew formula invocation, and refreshes detected capabilities after success. Do not bundle engines in the first release.
6. **Safe conversion pipeline:** stage output beside the destination in a unique temporary path, validate it, then move it to a collision-safe final name. Preserve sources, avoid overwrites, support cancellation and clean up only Morph-owned temporary files.

## Work phases

1. **Foundation:** package manifest, app entry point, app metadata, assets, ignore rules, development scripts and this plan.
2. **Core:** format/engine registry, capability probes, safe conversion job/output pipeline, native data/image/PDF operations and external process adapters.
3. **Application:** native dashboard, file picker/drop intake, Finder Service, format choice, batch queue, progress/cancel, history, output location and engine consent flow.
4. **Operations:** image resize, image/PDF metadata inspection, previewed batch rename copies, PDF merge/page-range extraction/split/compression, ZIP extraction and ZIP/TAR.GZ/7z repackaging, FFmpeg video trimming and batch compression, and JSON/YAML/TOML transformations are implemented and checked. Metadata inspection is read-only; metadata editing remains unimplemented. Keep the catalogue honest about unsupported font, CAD, geospatial and specialist conversions.
5. **Quality:** unit tests, fixture-based end-to-end tests, 12+ real format-pair conversions, security/failure/collision/cancellation checks, and a Finder smoke test.
6. **Documentation:** README, architecture and engine registration guide, tested capability matrix, known limitations, security/privacy notes, contribution guidance and third-party license attribution.
7. **Release:** reproducible arm64/x86_64 build where toolchain support permits, app archive/DMG, checksums, signing/notarization workflow, GitHub release and Cask audit. Do not ask users to bypass Gatekeeper.
8. **Install/distribute:** install to the current user’s Applications folder, register and verify Finder integration, exercise installed conversions, push all intended commits, and submit an upstream Cask PR only if the published artifact meets current Homebrew policy and GitHub access is available.

## Validation and release gates

- The self-contained SwiftPM harness currently reports 24 groups passed, 0 failed and 1 skipped locally, covering 31 distinct format pairs plus PDF page-range extraction, PDF compression, video trimming and compression, collision-safe batch rename copies, malicious ZIP and 7-Zip path/link rejection, image/PDF metadata inspection, route-aware conversion presets, selection-aware Finder output intersection, real engine conversions, safe outputs, source checksums, collision handling, invalid input, missing engines, fallback, cancellation, office-route family constraints and a large image. Video compression uses a generated 1080p H.264 fixture and checks size reduction, 720p dimensions, duration, collision handling and source preservation. The local 7-Zip conversion group skips when the optional engine is absent; arm64 CI installs it and verifies ZIP ↔ 7z. See `TEST_REPORT.md`.
- Cover mixed and batch inputs, unsupported/missing engines, failed and invalid inputs, collisions, cancellation, cleanup and large inputs where practical.
- GitHub Actions run [44225822929](https://github.com/Lakshay-13/morph/actions/runs/44225822929) on commit `2912c87` passed the real-file conversion checks on both macOS 26 arm64 and x86_64 runners. The arm64 job installed 7-Zip and exercised ZIP ↔ 7z; its universal-package job passed the Homebrew Cask audit and style checks, both architecture slices, signature and license checks, ZIP integrity and checksum verification. The packaged app has not been installed and launched on a physical Intel Mac; Cask install/uninstall are also unverified, and the CI archive remains ad-hoc signed.
- The earlier Quick Action build displayed Morph in Finder's built-in Quick Actions list and exercised PDF compression, PNG → JPEG, WebP, page-range extraction, metadata inspection and video trimming. That integration was superseded by the current Finder Sync submenu design. The live dependency confirmation was opened and cancelled; an install was not approved or run.
- The earlier helper build was launched from Quick Action with a selected PNG; the accessory helper stayed open while its format popover was shown, and the main Morph app stayed closed. The CUA accessibility surface did not expose the popover's format rows, so the older popover flow was not fully verified. The current Finder Sync submenu build and its missing live menu result are recorded below.
- The Finder Sync submenu build compiles and installs, but a fresh right-click on a PNG inside the monitored home folder did not show Morph. `pluginkit` lists the extension and its process runs; the app and extension are ad-hoc signed, `security find-identity -v -p codesigning` reports zero valid identities, and Xcode reports an existing or pending Apple Development certificate. Do not claim the new Finder submenu or its windowless click-through as live-tested until signing is resolved.
- Homebrew distribution requires a stable upstream artifact, checksum, local install/uninstall checks and Gatekeeper-compliant distribution. Homebrew's current self-submission policy normally requires 90 forks, 90 watchers or 225 stars; this repository currently has no independent-interest evidence. Recently released apps may receive further consideration only with substantial, independently verifiable public interest and multiple requests. Use a project-maintained tap for the initial release, then reconsider an official `homebrew/cask` submission if the project becomes eligible. Signing/notarization is blocked until an Apple Developer Program team with Developer ID access is available and its certificate and notarytool Keychain profile are configured. The GitHub Actions Cask audit and style checks pass; the local audit remains blocked because Homebrew prefers the existing CLT SDK over the selected Xcode SDK. Download Command Line Tools for Xcode 27.0 from Apple Developer Downloads before retrying the local audit.
- No engine or system dependency may be installed by the agent without a distinct explicit user approval.
