# Morph architecture

## Layers

- **MorphCore** owns format/category models, engine identity, capability discovery, routes, conversion requests, staged writes, validation, and engine adapters. The SwiftUI layer receives routes and does not invoke individual engines directly.
- **EngineRegistry** discovers candidates only in fixed system, Homebrew and MacPorts locations. It checks Keychain-pinned SHA-256 approvals before launching an external engine for version or capability probes; an unreviewed or changed binary remains visible in Engines but contributes no routes and is never run. After approval, version floors and actual capability probes determine routes. FFmpeg output routes also require the encoder used by Morph's adapter.
- **ConversionService** resolves an input extension, tries candidate routes in deterministic priority order, runs each registered `ConversionEngine`, validates the staged output and moves the first valid result to a unique destination. Atomic publication retries a numeric suffix if another process claims the selected name. A failed adapter's staged output is removed before the next route is attempted. The `ConversionEngine` protocol supports adding independent adapters.
- **MorphApp** provides Finder file selection through `NSOpenPanel`, drag/drop, format selection, batch execution, history, settings and explicit Homebrew actions. Convert and Operations share a selected-file list; Operations exposes the selection-aware resize, PDF, metadata, video and archive actions alongside batch rename. Settings control whether location tags are preserved; removal is the default. History can be cleared without deleting outputs. Detailed failures go to the `com.lakshaychawla.Morph` unified-log subsystem; UI status is concise and excludes raw engine output. When launched by the Finder helper with `--morph-background`, it changes to accessory policy and hides its window. `morph://show` reveals the window. Quit requests use `NSRunningApplication.terminate()` and the app cancels cancellable work, waits for cleanup, and refuses to quit if an operation cannot finish safely; there is no public `morph://quit` endpoint.
- **MorphFinderSync** supplies a selection-aware Finder contextual submenu. It uses `EngineRegistry` and `QuickConversionCatalog` to list only installed routes shared by the selected files, then starts or contacts the helper without reopening the main app. The sandboxed extension does not open the selected files itself.
- **MorphQuickConvert** is a persistent, windowless accessory helper for Finder conversion. It accepts a conversion URL only after validating the Apple Event sender's audit token against Morph's embedded Finder Sync code identity. On a cold launch, the extension starts the helper without request data in process arguments, then retries the same authenticated URL. A bounded request-ID ledger is atomically saved under Application Support before queueing, so retries remain deduplicated across helper restarts. The helper validates each request, rediscovers current engines, verifies their Keychain-pinned executable approvals and ignores an unprotected custom-output path from preferences. It uses the same `ConversionService` as the main app. Its menu-bar item shows progress and cancellation while converting, offers **Open Morph** and **Quit Morph**, and stays available until the user quits it. If the user quits during a conversion, the helper cancels that work and exits after cleanup.
- **MorphFileOperations** holds additional operations that are not simple format edges: read-only image/PDF metadata inspection, validated metadata-edit copies for PDFs and JPEG/TIFF images, image resize, previewed batch rename copies, PDF merge/page-range extraction/split/compression, ZIP extraction and FFmpeg video trimming. Metadata edits use PDFKit or ImageIO, stage beside the destination, validate the saved fields and dimensions/page count, then move to a collision-safe name. The original is never opened for writing. PDF merge snapshots are limited to 1,000 inputs and 1 GB total, and merged output is capped at 1 GB.
- **StructuredDataEngine** handles local JSON, YAML/YML, TOML, CSV/TSV and XML routes. Yams (with its bundled LibYAML) and swift-toml (with bundled toml++) are pinned SwiftPM dependencies; they are statically linked and their license texts ship in the app bundle. Parsing is size/depth/collection limited, and target-aware output estimates run before encoding with a 20 MB ceiling. JSON, XML, CSV and TSV estimates account for their actual string escaping; YAML and TOML use conservative bounds. Morph walks the YAML node graph under node, depth and scalar-expansion budgets before converting it to Foundation values; bounded aliases are accepted, oversized alias expansions and non-scalar mapping keys are rejected. CSV CRLF input is parsed by bytes, repeated-header expansion is estimated before row objects are materialized, and conversions reject extra columns or values the target representation cannot express.
- **ProcessRunner** starts absolute executable paths without a shell, bounds captured stdout/stderr, passes a minimal environment and validates explicit overrides, sets child signal masks/dispositions, applies a timeout and cancellation to the process group, and kills any surviving process-group members while the leader is still waitable. It observes exit with `waitid(WNOWAIT)` so the leader PID remains reserved during group signaling, and never signals a bare PID. After the leader is reaped, output readers stop if escaped descendants retain their pipes; the runner does not signal a stale process-group ID. Executable discovery ignores the inherited `PATH`; the Finder helper does not execute saved executable paths from preferences. Morph passes Homebrew's analytics/update requests and validated proxy variables, but Homebrew may override them or add Cask options from system, prefix and user `brew.env` files.

## Data flow

```text
Finder contextual menu ── selected URLs + available targets
              │ Convert To → [source → target]
              │ open helper with encoded request URL
              ▼
      MorphFinderSync extension ── builds contextual submenu
              │ launches the embedded helper
              ▼
      MorphQuickConvert accessory ── rechecks EngineRegistry routes
              │ ConversionRequest
              ▼
        ConversionService ── chooses ConversionEngine
              │ approved executable digest + argument array, no shell
              ▼
     unique staged output → validator → collision-safe final path

The main SwiftUI application is opened normally only when the user launches Morph directly or chooses **Open Morph** from the helper menu. For Finder conversions, the helper starts the main app in hidden accessory mode when needed and leaves it running. The Finder path does not activate or display a Morph window. The helper stays in the menu bar until the user chooses **Quit Morph**, which also exits the hidden main-app process.
```

The source file is not used as an output path. For ordinary conversions, an engine writes into a unique mode-`0700` workspace under macOS's protected temporary directory. Morph verifies the workspace identity before and after conversion, validates the output there, then copies the validated bytes using open directory descriptors into a second private stage under the selected output folder. The engine never writes through the selected output-folder path, so moving that folder cannot redirect converter output. The destination stage has inherited ACLs removed and is published with an exclusive atomic rename; a concurrent name collision retries with a numeric suffix rather than replacing a file. Published regular files use mode `0600` regardless of the source mode or umask, favoring privacy over preservation of executable bits and extended attributes. File operations also use descriptor-anchored private stages. Morph accepts an output parent only when it is owner-private or sticky and owned by the current account or root, on a writable local volume with ownership enabled; ACLs that allow child renames or inherit permissions are rejected. Read-only, network and ignore-ownership volumes fail closed. If the beside-source or configured destination does not meet those checks, the app and Finder helper use `~/Documents/Morph Output` and disclose the fallback. A PDF split uses one pinned stage for all pages and can roll back only the same regular files in that same pinned destination.

Batch rename is available from the app's Operations page. Morph previews a numbered prefix plus each complete original filename, so compound suffixes such as `.tar.gz` remain intact. It copies through the same private staging-directory mechanism, verifies the copied size, then publishes with an exclusive atomic rename. The source is never renamed or deleted. Cancellation stops before the next file and removes the active staging copy when possible.

## Finder integration

The primary Finder entry is the embedded `MorphFinderSync.appex`. It monitors the current user's home folder, `/Volumes`, `/Network` and `/Users/Shared`. For an item selection, `menu(for:)` reads `selectedItemURLs()` and intersects routes across all selected files. When Morph has published its engine snapshot, Finder uses the same installed-engine routes as the main app, including available ImageMagick, FFmpeg, Pandoc and LibreOffice adapters. If no snapshot exists yet, Finder uses a lightweight native fallback for ImageIO, PDF, structured data and macOS archive tools; optional-engine media and document routes require Morph to complete its first engine discovery. The contextual menu is **Convert To → [source → output]**, with source-aware format choices shown directly and no intermediate Morph submenu. For example, a PNG can offer **PNG → JPEG (.jpg)** when that route is available. Choosing a row sends one encoded request containing the selected paths and requested output format to the accessory helper; the extension does not attempt to open the source files because Finder Sync's selected URLs provide menu context, not file-read access. macOS may request Files & Folders permission from the helper for protected locations such as Downloads. The helper validates the paths and route again, performs the conversion with `ConversionService`, and shows progress/cancellation from its persistent menu-bar item. It does not open the main Morph window or a format picker. Its menu also offers explicit **Open Morph** and **Quit Morph** actions. The helper preserves sources and writes to collision-safe destinations.

The main app uses a single SwiftUI `Window` scene and handles `morph://show` to reopen it. The windowless helper accepts sender-checked `morphquick://convert` requests from Finder Sync; it does not route those requests through the main app or open a window. Launching the app starts the windowless helper. Closing the main window switches the app to accessory activation policy, keeping both processes available without a Dock entry. Finder starts the helper directly; the helper starts the main app hidden only when it is not already running, so a conversion does not reopen a closed Morph app or restore its Dock entry. The helper's **Open Morph** action brings the singleton window back.

The contextual submenu appears directly in Finder's right-click menu; macOS does not provide an API for inserting a dynamic submenu inside its built-in **Quick Actions** section. Apple's Finder Sync guidance describes that extension point as sync-oriented and recommends it for synchronization status/control. The extension performs no conversion itself; conversion stays in the accessory helper. For a cold helper launch, the extension launches the helper without request data in arguments, then sends the same sender-checked URL up to four times while the helper starts. A request ID makes retries idempotent. The helper checks selected paths on a serial background queue, displays a Files & Folders permission wait state, and reports a retry message after 60 seconds. The wait timeout does not interrupt a file-open request already blocked inside macOS TCC. This locally installed ad-hoc build displayed the menu and completed a cold-start conversion, but ad-hoc signing is not suitable for public distribution and may be treated differently on other Macs. See [Apple's Finder Sync programming guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html).

## Engine discovery and selection

`EngineID` records each engine's identifier, display name, executable candidates and Homebrew package name/type. `EngineRegistry.discover()`:

1. Queries ImageIO for native readable/writable type identifiers, then intersects them with Morph's explicit common-raster allowlist and checks input content against the file extension before decoding.
2. Finds external tools only in fixed Homebrew/MacPorts/system directories; it does not trust the process `PATH`.
3. Lists an unapproved candidate without executing it. Morph's Engines screen displays its resolved path and SHA-256; signed builds store approval in a team-prefixed Data Protection Keychain group shared by the Morph app and Finder helper. Ad-hoc builds cannot persist this trust state, so external engines and Homebrew actions remain unavailable. The helper repeats the digest check before discovery and execution. A changed executable requires review again.
4. For approved engines, runs fixed version/capability queries such as `ffmpeg -demuxers`, `-muxers`, `-encoders`, ImageMagick's format listing, Pandoc's reader/writer listings, and LibreOffice's headless version probe.
5. Produces conversion routes only for approved engines that pass the version floor and expose the required capabilities.

Routes are deterministic: built-in adapters are preferred, followed by FFmpeg/Pandoc, then other optional adapters. Morph blocks external engine versions below the reviewed floors (FFmpeg 9.0.2, ImageMagick 7.1.2-36, Pandoc 3.14, Ghostscript 10.08.0, 7-Zip 26.06 and supported LibreOffice branches 26.2.7/26.8.2), and does not probe external capabilities until the executable digest is approved and the version check passes. External engine probes have a 10-second timeout. Version parsing requires the expected engine banner; unrelated compiler or library versions cannot satisfy a floor. Route creation also requires an engine's `canConvert` status, so unapproved or blocked engines are not advertised. Morph requires Pandoc's current upstream release because its security policy provides updates only for the latest release. Pandoc's adapter excludes PDF output, CSV and generic JSON AST conversion, and `--extract-media`; its `--sandbox` option alone does not mitigate GHSA-xj5q-fv23-575g. Ghostscript's floor addresses CVE-2026-39919, and compression rechecks the executable before reading a PDF. PDF text extraction uses PDFKit, so Poppler is not invoked. Ghostscript provides a PDF-compression operation outside the route graph. 7-Zip provides ZIP ↔ 7z archive routes only when `7zz` or `7z` is installed, approved, and passes its version gate. Its adapter validates 7z member paths and rejects link entries before extraction. `libvips` is not auto-discovered because Morph has no adapter for it.

The version parser examines only the first nonempty line of each engine's version output; a later banner cannot override an unrecognized first line.

## Archive extraction boundary

ZIP, TAR and 7z extraction use the macOS system `libarchive` reader; Morph does not bundle a separate archive parser or extract by running a user-selected command. Before parsing, Morph opens the selected archive non-blocking and copies that regular file into a mode-0700 temporary directory whose ACL is cleared before writing, enforcing a 2 GB compressed-input limit. The reader consumes that snapshot, so validating an archive and later extracting a different file at the original path is avoided. Each suffix enables only its expected archive format and compression filter; external-program filters are not enabled. ZIP additionally receives a local/central header consistency check. Extraction permits only regular files and directories, rejects links, special files, unsafe paths and collisions according to the destination volume's case-sensitivity and Unicode normalization, and limits the archive to 10,000 entries and 10,000 created filesystem objects, including implicit directories, 512 MB per file and 2 GB expanded total. The object budget is checked before creating each archive member's filesystem path. Expanded bytes are counted as they are decompressed and written. Output uses pinned directory descriptors plus `openat`/`mkdirat`, no-follow and exclusive-create flags, preventing a path replacement from redirecting writes. Direct ZIP extraction pins the containing directory, output parent and private staging directory. The parent must be owner-private or sticky and owned by the current account or root, with no ACL child-rename grant or inherited ACL; the staging ACL is cleared and mode is forced to 0700 before extraction. Publication uses an exclusive atomic rename. Failure cleanup traverses the stage and removes a newly created output folder relative to its pinned containing-directory descriptor. Archive repackaging uses a separate `libarchive` writer to stream validated regular files and directories from the snapshot straight into the new archive. It checks names using case-sensitive archive semantics, so valid names that differ only by letter case survive even when the temp volume is case-insensitive. Repackaged ownership is reset and special permission bits are removed. Direct extraction keeps files private and non-executable. Cancellation is polled during snapshotting, entry reads and writes. The limits do not protect against defects in Apple's system `libarchive` implementation itself.

Video trimming and compression are FFmpeg operations outside the general route graph. Trimming checks the source duration, re-encodes the requested interval as H.264/AAC MP4 and validates the output duration. Compression accepts batches, exposes quality and maximum-resolution choices, re-encodes to H.264/AAC MP4 and validates duration and dimensions. Both use unique staged destinations, preserve originals and support process cancellation. Compression reports actual aggregate input and output sizes because re-encoding can enlarge already-compressed media. The confirmation explains quality changes and possible subtitle/metadata loss. If FFmpeg is absent, Morph asks before offering installation and retries after approval.

## Dependency actions

The engine screen is the place to manage packages. If a conversion needs an unavailable engine, Morph explains why and asks for confirmation before running Homebrew. Morph does not fetch bottle-size metadata before approval; Homebrew resolves package and dependency downloads after the user confirms. After an approved install succeeds, Morph refreshes engine discovery, requests approval for the newly installed executable when needed, and retries that conversion only after approval. Individual installs, updates and uninstalls use explicit confirmation. **Update All** checks installed engines shown by the manager, then lists the exact outdated packages before asking once for approval. It groups formulae and casks separately and invokes Homebrew only for those packages. Before any Homebrew command, Morph also requires a reviewed executable digest; this is separate from the package-action confirmation. The confirmation discloses that Homebrew can upgrade dependencies and outdated dependents, close a running updated application and clean older package versions. LibreOffice uses Homebrew's cask actions; other optional engines use formulas. A single-operation gate disables engine controls while checks, confirmation or Homebrew actions are active, preventing duplicate or concurrent package-manager operations. Homebrew verifies package checksums. Network availability and the Xcode license state can prevent Homebrew from running.

## Local storage

- User settings use `UserDefaults` under the `com.lakshaychawla.Morph` key.
- External executable approvals, the custom output-directory identity and the private-stage HMAC key use the signed app/helper's shared Data Protection Keychain group. Missing or stale approvals fail closed; an ad-hoc build cannot persist approvals or custom output settings. Stale-stage cleanup removes only directories with an authenticated marker; if secure storage is unavailable, cleanup leaves old stages alone.
- Conversion history is stored at `~/Library/Application Support/Morph/history.json`. App/helper updates use an advisory file lock, merge by UUID and atomically write a private file to avoid losing concurrent Finder conversions.
- No input content is stored in history. No telemetry is implemented.

## Product limits

The current package has no conversion-plugin loader or update service. Engines are fixed adapters in the application. The Finder extension is sandboxed and handles selection/menu work only; the accessory helper performs conversion. The Finder submenu is not part of the built-in **Quick Actions** section, and Finder Sync is documented primarily for sync-related UI. The extension monitors the home folder, mounted volumes, network shares and `/Users/Shared`; ad-hoc local builds may not surface the extension in Finder.

ImageIO output identifiers are intersected with the explicit common-raster allowlist and verified with a private 2 × 2 probe image. This prevents unreviewed types such as RAW, PSD, EXR and KTX from reaching the in-process decoder. The detected input type must match the extension before decode or metadata access. Direct image and PDF file operations snapshot user-selected inputs before parsing. Image outputs are checked against their requested UTI before validation, and PDF outputs receive a header check before PDFKit opens them. External engines run with writes denied except for declared private stages and `/dev/null`; separate rules deny hard links, clones, Apple Events, LaunchServices opens, launchd job creation, arbitrary process execution, process forks, signals to other processes, preference reads/writes, and selected sensitive Mach service lookups. It permits execution only of the exact approved engine binary, while preserving other default reads and unlisted Mach lookups for compatibility. Morph rejects engine outputs unless they are regular files owned by the current user with one hard link. LibreOffice's launcher is accepted only in its exact two-line form; its target must be in the expected app/Caskroom location and pass strict nested code-signature validation for the expected Team ID and bundle identifier. LibreOffice output is copied into a separate Morph-owned stage before validation or sanitization so a child process cannot change the validated bytes.
