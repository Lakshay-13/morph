# Security policy

## Reporting a vulnerability

Please report a security issue privately to the repository owner through GitHub's private vulnerability reporting feature, if enabled. Include the affected Morph version, macOS version, reproduction steps and impact. Do not attach private files or credentials.

## Current security boundaries

- Conversion is local. Morph does not send file contents to a service.
- The main app and Finder helper enable Launch Services quarantine for files they create, so outputs and extracted items receive macOS quarantine handling by default. Morph's private Application Support data is excluded. Gatekeeper retains its normal checks when a generated executable is opened.
- Optional external engines are found only in fixed Homebrew, MacPorts and system locations. Discovery does not run an unapproved engine. Before probing or conversion, Morph checks the executable and its parent directories for trusted ownership, restrictive mode bits and ACL write grants, then compares the executable's SHA-256 with a user-reviewed value stored in the Data Protection Keychain under a team-prefixed access group shared by the signed app and Finder helper. The Engines screen shows the executable path, owner and digest before approval and supports revocation. A local ad-hoc build has no trusted team access group, so optional engines, Homebrew actions and custom output-folder approvals fail closed; built-in conversions remain available. Homebrew itself follows the same review gate, and each install, update or uninstall still requires a separate action confirmation. Morph does not fetch bottle-size metadata before that confirmation. It asks Homebrew to disable analytics and automatic self-updates and passes configured proxy variables. Homebrew also loads `brew.env` from `/etc/homebrew`, the active prefix's `etc/homebrew`, and its user configuration directory (normally `~/.homebrew`, or an XDG path); these files may override Morph's environment settings or supply Cask options, so users should inspect their trusted Homebrew configuration before approving an action. Approved Homebrew actions run outside the conversion sandbox and cannot be safely cancelled after package execution begins; the reviewed `brew` executable does not pin the Ruby formula/cask code it later downloads.
- Process adapters use absolute executable paths and argument arrays, not shell command strings. The runner passes a minimal environment, closes unrelated inherited file descriptors, bounds stdout and stderr capture, sets child signal masks and dispositions explicitly, applies a timeout and cancellation, and kills remaining process-group children while the leader is still waitable. If escaped descendants keep output pipes open after the leader is reaped, readers are stopped without signaling the now-stale process-group ID.
- Ordinary conversions write engine output into a unique mode-`0700` workspace under macOS's protected temporary directory. Morph validates that result, then copies it through open directory descriptors into a second private stage anchored to the selected output folder and publishes through an exclusive atomic rename. If another process claims the proposed name at publication time, Morph retries with a numeric suffix and never replaces that file. Converters never write through the user-selected output-folder path. File operations use unique descriptor-anchored stages; Morph clears inherited ACLs before use, validates output and preserves originals. Published regular files, including batch-renamed copies, use mode `0600` regardless of source mode or umask; this privacy choice can remove executable bits and extended attributes from copies. Created extraction directories use mode `0700`. Output parents must be owner-private or sticky and owned by the current account or root, without ACL child-renaming or inheritance rights, and must be on a writable local volume with ownership enabled. Read-only, network and ignore-ownership volumes are rejected before staging. A PDF split pins one destination stage for the full operation and rolls back only regular files whose identities still match that pinned directory.
- Archive extraction opens input non-blocking and rejects non-regular files before snapshotting, then processes that exact snapshot with macOS's system `libarchive`. Morph clears the snapshot folder ACL and forces mode `0700` before writing the copied archive. ZIP uses only libarchive's seekable reader, rejects ZIP64 and oversized comments, and requires the central directory to end exactly at the end record; ZIP, TAR and 7z otherwise enable only the suffix-appropriate format and compression filter, with no external-program filters. It accepts only regular files and directories, rejects unsafe or colliding paths and links, and enforces entry, filesystem-object, per-file and expanded-byte limits before or while writing. Writes are relative to pinned directory descriptors with no-follow and exclusive-create flags. Direct ZIP extraction pins the containing, output-parent and stage descriptors through exclusive atomic publication, checks that the selected output path still resolves to the pinned parent before and after publishing, and does not return a stale result URL if the folder moved. Stable symlink-selected output folders remain supported by comparing the resolved directory identity. The output parent must be owner-private or sticky and owned by the current account or root. ACLs that allow child renames or inherit permissions are rejected, and Morph clears ACLs from its new staging directory before writing extracted files. Failure cleanup is descriptor-relative. Direct extraction uses private non-executable files. Archive repackaging validates the snapshot then streams regular file and directory entries through the system `libarchive` writer, preserving case-distinct names without materializing members on the temporary volume; it resets ownership and strips special permission bits. The limits are 2 GB compressed input, 10,000 archive entries, 512 MB per file, and 2 GB expanded total. Cancellation is checked during snapshotting, entry reads and writes.
- Archive conversion normalizes member permissions to owner-only, retaining only the owner's executable bit, and preserves available member modification times. ZIP ↔ 7z uses a private intermediate extraction stage with the same permissions policy. These conversions do not preserve group/other access bits.
- Structured-data inputs have a 10 MB limit. YAML's node graph is checked for combined indentation/flow depth, node count, scalar expansion and mapping-key type before constructing Foundation values; large alias expansions and collection mapping keys are rejected.
- Structured-data conversions estimate output using the target format's escaping rules for JSON, XML, CSV and TSV, with conservative bounds for YAML and TOML, and reject output above 20 MB. CSV/TSV transformations also cap records, columns and padded cell count, estimate repeated-header output before materializing row dictionaries, preserve explicit all-empty records while skipping blank lines, and detect ASCII delimiters at the byte level so combining Unicode marks cannot hide a delimiter from quoting. CSV exports prefix spreadsheet formula-like strings with an apostrophe while preserving finite negative numbers as numbers. XML input that would collide with Morph's reserved `_text` representation is rejected instead of silently losing parent text.
- PDF rendering and multi-frame image conversions enforce input, page/frame, pixel, generated-byte and available-space budgets. PDFs are limited to 512 MB and 1,000 pages; a rendered page is capped at 16 million pixels and an operation at 256 million pixels/1 GB generated output. Images are limited to 512 MB, 250 frames, 32 million pixels per frame and 256 million pixels total, including image resize and image-to-PDF paths. Cancellation is checked between frames/pages and around synchronous ImageIO/PDFKit calls, but cannot interrupt a single framework decode or page draw. After a user requests quit, Morph cancels work and allows 60 seconds for it to stop before exiting; a stuck parser may leave a private incomplete stage for later cleanup. Stale Morph stages are removed only when old enough and their owner, mode, type and inode match and a Keychain-HMAC sibling marker authenticates the generated directory name. The marker stays outside staged contents so an archive or other conversion cannot expose it or collide with a legitimate file. If secure marker storage is unavailable, cleanup leaves stale directories alone, including after a crash or forced quit.
- Finder conversion request IDs are stored in a bounded ledger under Application Support before work is queued. This makes the Finder extension's startup retries idempotent across helper process restarts. Input access checks run on a serial background queue so Files & Folders prompts do not block the helper's Apple Event/UI thread. The helper displays a wait state and reports a retry after 60 seconds; this timeout cannot interrupt a file-open request already blocked inside macOS TCC. If the ledger cannot be read or written safely, the helper does not queue a request carrying an ID.
- Location metadata removal is enabled by default for image and media conversions, metadata-copy edits, video trims and compression. ImageIO removes GPS and IPTC location fields, including city, sub-location, region and country values. ImageMagick removes EXIF, XMP and IPTC profiles because it cannot reliably remove only GPS tags across every supported container; ICC color profiles and decoded pixels are retained. FFmpeg removes common QuickTime location tags, including name, body and note, from container and stream metadata. Image-to-PDF rasterizes pixels into a fresh bitmap before PDFKit writes the page, so source image metadata is not copied into the PDF. The Settings toggle can preserve location tags for users who choose that tradeoff on supported image and media routes. PDF operations may preserve document metadata where PDFKit does so.
- Conversion history can be cleared from the History screen. Clearing writes an empty history record under the existing private file and lock checks; it does not delete converted outputs.
- Each ImageMagick conversion uses a private temporary policy that denies delegates, indirect reads and non-raster coders, and sets resource limits. This reduces exposure to unnecessary ImageMagick features; it is not an OS sandbox for the parser.
- External conversion engines run through a fail-closed macOS sandbox profile that denies file writes by default except for `/dev/null` and Morph's private stages, network access, reads/writes under the current user's home directory, common temporary roots, `/Users/Shared`, mounted volumes, and writes to Homebrew and system installation prefixes. It separately denies hard links and file clones, because those are not covered by ordinary file read/write rules. It also denies Apple Events, LaunchServices opens, launchd job creation, process execution except for the exact approved engine binary, process forks, signals to other processes, preference reads/writes, and lookup of the `cfprefsd` daemon/agent, pasteboard, active WindowServer and Core Animation rendering services. Each conversion adds read/write exceptions only for canonical mode-`0700` Morph staging directories and an exact read exception for the approved executable; it sets a private `HOME` and cache, and the engine never receives the original input path. Engine-produced files must be regular files owned by Morph's user with exactly one hard link before validation and publication; LibreOffice output is copied into a second private snapshot under the same check. The profile still allows macOS default reads and unlisted Mach service lookups; it is not a complete read or IPC sandbox. Per-user fonts in `~/Library/Fonts` may be unavailable to document engines, which could substitute fonts; this has not been integration-tested. Morph itself and its in-process parsers are not OS-sandboxed.
- LibreOffice output is copied into a second Morph-owned private snapshot before validation or spreadsheet sanitization. The engine sandbox does not grant that snapshot path, so a surviving engine child cannot alter the bytes Morph validates or publishes. Structured-data validation opens only regular non-symlink files.
- Native ImageIO routes are limited to common raster formats Morph explicitly supports and validate that the detected file type matches its extension before decoding or reading metadata. Metadata inspection and editing use private input snapshots. Direct image resize and PDF merge, split, page extraction and compression also snapshot selected inputs before parsing. Other ImageIO-readable types such as RAW, PSD, EXR or KTX are not routed through the in-process decoder. ImageIO and PDFKit remain in-process and are not OS-sandboxed.
- PDF merge snapshots are capped at 1,000 inputs and 1 GB combined; generated merged PDFs are capped at 1 GB. PDF input snapshots are single-file bounded at 512 MB.
- FFmpeg/FFprobe are restricted to the `file` protocol and their versions and approved executable digests are checked before conversion and generated-media validation. Generated image outputs are checked against their requested Uniform Type Identifier before ImageIO decodes them; PDF outputs must begin with `%PDF-` before PDFKit opens them. FFmpeg output uses a 2 GB file-size limit, and Morph requires FFprobe to validate every generated audio/video file. Media inputs also receive a demuxer whitelist based on their extension. LibreOffice uses a private per-conversion profile under the external-engine sandbox and has a 2 GB output limit. Morph accepts only the expected LibreOffice app location and a strict nested code-signature validation for `org.libreoffice.script` signed by The Document Foundation's Developer ID team; its two-line Homebrew launcher must contain one exact literal target, and Morph runs the native `Contents/MacOS/soffice` binary directly. A private CSV-to-XLSX capability probe must pass before LibreOffice routes are advertised; a failed or timed-out probe disables those routes. Engine capability probes time out after 10 seconds. Pandoc is invoked with `--sandbox`, and its version is also gated; `--sandbox` alone does not mitigate every Pandoc vulnerability. Ghostscript's version is checked before PDF compression reads the PDF, the PDF header must begin at byte zero with `%PDF-`, and Ghostscript runs under the external-engine sandbox. 7-Zip's version is checked before archive creation and integrity validation.
- A custom output-folder preference is not trusted from `UserDefaults` alone. In signed builds, Morph compares the selected path and directory identity with a Data Protection Keychain record shared with the Finder helper. If the saved folder is stale or the selected filesystem cannot support Morph's private staging checks, Morph saves to `Documents/Morph Output` and tells the user.
- Morph does not bundle external conversion engines.

Morph is not OS-sandboxed in this SwiftPM build. It needs file access to the user-selected input and configured output location. Its external-engine children are separately constrained by the macOS process sandbox described above, but parsers compiled into Morph remain in the app's privacy context. For protected folders such as Downloads, macOS may request Files & Folders access for the Finder helper; this is folder-level consent, while Morph's Finder workflow processes only the paths selected by the user. Homebrew Cask removal does not remove Keychain executable approvals; revoke approvals in Morph before uninstalling, or remove the `com.lakshaychawla.Morph.engine-executable-approvals.v2` items in Keychain Access after removal. These controls reduce specific attack surfaces; they do not eliminate vulnerabilities in macOS frameworks, system `libarchive`, ImageIO, PDFKit or third-party parsers/codecs. Treat engines as separate software, keep them current through their package manager, and avoid processing untrusted files with outdated engines. The locally built app is ad-hoc signed; it has not passed Gatekeeper assessment, Developer ID signing or notarization.

Executable digest approval pins the main executable file, not its dynamically loaded libraries, codecs, scripts or other files in an engine's installation. It also cannot make a time-of-check/time-of-use race impossible. Morph is not OS-sandboxed, and an approved engine runs with the current user's permissions within the limits the macOS sandbox profile enforces. The sandbox still permits macOS default reads outside its protected paths and Mach lookups not explicitly denied above. These are residual risks; a zero-vulnerability claim is not warranted.

External parser versions are checked against reviewed security floors during discovery and again before execution: FFmpeg 9.0.2, ImageMagick 7.1.2-36, Pandoc 3.14, Ghostscript 10.08.0, 7-Zip 26.06, and LibreOffice 26.2.7 or 26.8.2 for the corresponding release branch. Pandoc's [upstream policy](https://github.com/jgm/pandoc/security/policy) supports only its latest release, so Morph requires 3.14, the current release at this review ([release history](https://pandoc.org/releases.html)). A failed or unparseable version check disables the affected capability. These minimums address specific reviewed advisories; they do not establish that any dependency is vulnerability-free. The Pandoc adapter excludes PDF output and `--extract-media`; `--sandbox` is not sufficient to mitigate GHSA-xj5q-fv23-575g by itself. Ghostscript 10.08.0 addresses the reviewed CVE-2026-39919 floor.
